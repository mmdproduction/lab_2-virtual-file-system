# Техническое задание
## Виртуальная файловая система с индексированным поиском и управлением доступом

### 1. Назначение программы

Разработать на C++ приложение для организации существующих файлов в виртуальную иерархию каталогов, поиска файлов и управления доступом пользователей.

Программа должна позволять сравнивать производительность индексов на основе обычного бинарного дерева поиска — BST — и сбалансированного AVL-дерева.

Виртуальная структура существует независимо от физического расположения файлов. Прикрепление, переименование, перемещение и удаление виртуальной записи не должны изменять исходный файл.

### 2. Состав и границы проекта

В проект входят:

- виртуальные файлы и каталоги;
- собственные контейнеры данных;
- индексы на основе BST и AVL;
- пользователи, группы и наследуемые права доступа;
- сохранение и загрузка состояния;
- графический интерфейс;
- автоматические тесты;
- средства измерения производительности и экспорта результатов.

Программа не реализует размещение файлов по секторам диска, драйвер файловой системы или изменение прав доступа операционной системы. Права действуют внутри приложения.

### 3. Архитектура

#### 3.1. Основные подсистемы

| Подсистема | Ответственность |
|---|---|
| Контейнеры | Собственная последовательность, BST, AVL, словари и итераторы |
| Виртуальная ФС | Хранение объектов и выполнение операций над виртуальной иерархией |
| Поиск | Построение и обновление индексов, поиск по имени |
| Управление доступом | Пользователи, группы, вычисление действующих прав |
| Сохранение состояния | Запись и восстановление структуры, ссылок и политик доступа |
| Эксперименты | Генерация данных, проверка результатов и измерение времени |
| Интерфейс | Ввод команд и отображение состояния программы |

Логика файловой системы, поиска и прав доступа должна работать независимо от графического интерфейса.

#### 3.2. Модель данных

**Виртуальный объект** содержит:

- уникальный устойчивый идентификатор;
- имя;
- тип: файл или каталог;
- идентификатор родительского каталога;
- правила доступа и признак наследования.

**Виртуальный файл** дополнительно содержит путь к существующему физическому файлу.

**Виртуальный каталог** содержит собственную последовательность идентификаторов дочерних объектов.

Полный виртуальный путь вычисляется по цепочке родительских каталогов.

Идентификатор объекта сохраняется при переименовании и перемещении. В одном каталоге не допускаются объекты с одинаковыми именами. Сравнение имён выполняется с учётом регистра.

#### 3.3. Иерархия и поисковые индексы

Иерархия каталогов и поисковые деревья являются отдельными структурами.

Иерархия описывает отношение «каталог содержит объект». Индекс хранит соответствие:

**имя файла → собственная последовательность идентификаторов файлов.**

Несколько файлов с одинаковым именем могут находиться в разных каталогах.

BST и AVL должны реализовывать общий интерфейс словаря с операциями добавления, поиска, проверки наличия и удаления ключа. Деревья должны быть шаблонными.

Виртуальная ФС является основным источником данных. Индексы являются производными структурами и должны допускать полное перестроение обходом ФС.

#### 3.4. Взаимодействие подсистем

Обработка команды выполняется в следующем порядке:

1. Проверка входных данных и прав пользователя.
2. Проверка допустимости операции.
3. Изменение виртуальной структуры.
4. Обновление поисковых индексов.
5. Обновление отображения.

При отклонении операции состояние программы должно сохраняться. После успешной операции структура ФС и индексы должны быть согласованы.

### 4. Функциональные требования

#### 4.1. Операции виртуальной ФС

Программа должна создавать корневой каталог и позволять создавать вложенные каталоги.

Добавление виртуального файла должно выполняться прикреплением существующего физического файла. Программа должна проверять существование файла при прикреплении.

Пользователь должен иметь возможность просматривать содержимое каталога, виртуальный путь и сведения о выбранном объекте.

Программа должна поддерживать переименование виртуальных файлов и каталогов.

Программа должна поддерживать перемещение объектов между виртуальными каталогами. Запрещается перемещать каталог в себя или своего потомка.

Программа должна поддерживать удаление виртуальных файлов и пустых каталогов. Удаление корневого каталога запрещается.

Удаление, перемещение и переименование виртуальной записи не должны изменять физический файл.

Программа должна отклонять пустые имена, имена `.` и `..`, имена с разделителем виртуального пути `/`, а также повторяющиеся имена внутри одного каталога.

Если ранее прикреплённый физический файл стал недоступен, виртуальная запись должна сохраняться и отображаться с соответствующей отметкой.

#### 4.2. Поиск

Программа должна выполнять точный поиск виртуальных файлов по имени с использованием BST или AVL.

Пользователь должен иметь возможность выбрать реализацию индекса. Результаты поиска обеих реализаций должны совпадать.

Результат должен содержать все доступные пользователю совпадения с указанием виртуальных путей.

Индексы должны обновляться после добавления, переименования и удаления файлов. Перемещение каталога не должно приводить к неверным путям в результатах.

Должны поддерживаться обход индекса через итератор и его полное перестроение.

#### 4.3. Пользователи и права доступа

Программа должна поддерживать пользователей и группы. Пользователь может состоять в нескольких группах.

Предусматриваются следующие права:

- **просмотр** — просмотр объекта и содержимого каталога;
- **изменение** — изменение содержимого каталога;
- **управление доступом** — изменение правил доступа объекта.

Правила назначаются группам. Разрешения всех групп пользователя объединяются. Явные запреты в первой версии не используются.

При включённом наследовании объект получает разрешения родительского каталога в дополнение к собственным. При отключённом наследовании учитываются только собственные правила. Отсутствие разрешения означает отсутствие доступа.

Просмотр объекта требует права просмотра самого объекта и всех каталогов на пути к нему.

Создание и прикрепление требуют права изменения целевого каталога. Удаление и переименование требуют права изменения родительского каталога. Перемещение требует этого права для исходного и целевого каталогов.

После перемещения действующие наследуемые права должны определяться новым расположением объекта.

Должен существовать администратор, управляющий пользователями и группами и имеющий полный доступ. Переключение текущего пользователя используется для демонстрации; проверка паролей в объём проекта не входит.

#### 4.4. Сохранение состояния

Программа должна сохранять и загружать:

- виртуальные объекты и их идентификаторы;
- связи между каталогами и файлами;
- пути к физическим файлам;
- пользователей и группы;
- правила доступа и настройки наследования.

Сохранение выполняется в структурированном текстовом формате с указанием версии. Содержимое физических файлов не копируется.

После загрузки индексы должны восстанавливаться из виртуальной структуры.

Повреждённые данные, повторяющиеся идентификаторы, отсутствующие родители и циклы должны обнаруживаться до замены текущего состояния. Ошибка загрузки не должна разрушать открытый проект.

#### 4.5. Интерфейс

Используемый инструмент — **Qt Widgets**.

Интерфейс должен предоставлять дерево виртуальных каталогов, содержимое выбранного каталога, поиск и сведения о выбранном объекте.

Через интерфейс должны быть доступны файловые операции, управление правами, переключение пользователя, сохранение и загрузка.

Интерфейс должен отображать сообщения об ошибках и позволять просматривать исходные данные и результаты алгоритмов.

Графические компоненты должны обращаться к собственным структурам проекта через адаптеры. Хранение файловой иерархии и выполнение поиска не должны подменяться готовыми моделями и алгоритмами GUI-библиотеки.

#### 4.6. Измерение производительности

Программа должна поддерживать ручной ввод ключей и автоматическую генерацию наборов для проверки индексов. Пользователь задаёт размер набора и начальное значение генератора.

Обязательное сравнение — время построения BST и AVL на одинаковых данных при трёх порядках ключей:

1. По возрастанию.
2. По убыванию.
3. В случайном порядке.

Дополнительно должно измеряться время точного поиска существующих и отсутствующих ключей.

Результаты должны отображаться в интерфейсе и экспортироваться в CSV.

### 5. Нефункциональные требования

**Язык и сборка.** Используется C++17 или новее. Сборка должна быть воспроизводима через CMake в документированной среде.

**Собственные контейнеры.** Контейнеры прикладных данных, включая последовательности, словари и вспомогательные коллекции, реализуются самостоятельно. Внутренние структуры сторонней GUI-библиотеки не используются вместо этих реализаций.

**Стиль.** Собственный C++-код оформляется по Google C++ Style Guide. Имена переопределяемых методов сторонних интерфейсов сохраняются согласно их API.

**Модульность.** Основные алгоритмы должны тестироваться без запуска графического интерфейса. Подсистемы взаимодействуют через явно определённые интерфейсы.

**Управление памятью.** Реализация должна корректно освобождать память и исключать выходы за границы, повторное освобождение и обращение к уничтоженным объектам.

**Целостность.** После операций сохраняются уникальность идентификаторов, отсутствие циклов, корректность родительских связей и согласованность индексов.

**Эффективность.** Поиск ключа в AVL должен требовать `O(log U)` сравнений, где `U` — число уникальных ключей. Получение всех совпадений дополнительно требует обработки соответствующего списка.

**Обработка ошибок.** Некорректный ввод и отказ в доступе должны приводить к понятному сообщению. Отклонённая операция не должна оставлять частично изменённые данные.

### 6. Методы оценки качества

#### 6.1. Автоматические тесты

| Объект проверки | Основные случаи |
|---|---|
| Последовательность | Пустое состояние, рост вместимости, удаление, границы, независимость копий |
| BST и AVL | Добавление, поиск, удаление, отсутствующие ключи, пустое дерево |
| Балансировка AVL | Четыре вида поворотов, баланс после вставок и удалений |
| Виртуальная ФС | Прикрепление, переименование, перемещение, удаление, повторяющиеся имена |
| Индексы | Несколько совпадений, обновление после операций, перестроение |
| Доступ | Несколько групп, наследование, его отключение, перемещение, отказ в операции |
| Сохранение | Восстановление состояния, повреждённый файл, отсутствующий физический файл |

После изменений AVL автоматически проверяются порядок ключей, корректность высот и разность высот поддеревьев не более единицы.

Результаты поиска сравниваются с эталонным линейным просмотром собственной последовательности. Для случайных последовательностей операций BST и AVL должны давать одинаковые результаты.

#### 6.2. Проверка сохранности файлов

На тестовых физических файлах до и после виртуальных операций сравниваются:

- существование;
- имя и расположение;
- содержимое.

#### 6.3. Проверка производительности

Для каждого размера набора и порядка ключей выполняется не менее пяти повторов. Перед каждым построением используется пустой индекс.

Замеры выполняются монотонными часами. Генерация данных, отображение интерфейса и экспорт исключаются из измеряемого участка.

Фиксируются:

- алгоритм;
- количество записей и уникальных ключей;
- порядок входных данных;
- номер повтора;
- время построения;
- высота дерева;
- время выполнения серии поисковых запросов.

Для сравнения используется медиана времени. В отчёте указываются оборудование, компилятор, параметры оптимизации и начальное значение генератора.

Обязательное превосходство AVL на каждом небольшом наборе не устанавливается: оцениваются корректность измерений и объяснение наблюдаемого поведения.

### 7. Критерии приёмки

Работа считается завершённой, если:

1. Выполнены функциональные требования.
2. Основные алгоритмы покрыты автоматическими тестами, все приёмочные тесты проходят.
3. Подтверждена сохранность физических файлов.
4. BST и AVL возвращают одинаковые результаты поиска.
5. Права доступа проверяются внутри логики программы независимо от состояния кнопок интерфейса.
6. Сохранение и загрузка восстанавливают эквивалентное состояние.
7. Выполнено сравнение построения деревьев для трёх порядков данных.
8. Результаты экспериментов доступны в CSV.
9. Предоставлены инструкция по сборке и запуску, описание архитектуры и анализ результатов.
